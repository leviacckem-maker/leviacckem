介绍

17TRACK API 是一个物流查询接口。通过 API 可以查询 17TRACK 支持的 3,487 家运输商的物流信息。API 基于 HTTP 协议，与开发语言无关，采用「先注册单号、再推送信息」的 WebHook 机制，全程自动跟踪物流。

V2.4 主要更新

V2.4 不向下兼容，仍可继续使用 V1 或 V2.2 及以下版本。

额外附加信息传参注册时把邮编、国家、发货日期、手机尾号等附加信息分别传入，17TRACK 按各运输商的查询要求自动选用。
运输商原生多语言运输商官方支持的语言直接返回官方描述，不支持时可选默认语言或第三方翻译。
新增 provider_tips返回运输商官方的运输提示，例如轨迹异常的说明。
新增 sync_status获取列表时标识运单是否已从运输商处同步轨迹成功。

快速开始

确保已注册 API 账号。新账号注册时一次性赠送 200 个免费单号额度。

1
定义 WebHook 接口

自行编写一个接收推送的 URL，也可以先用 webhook.site 的免费接口验证。登录 API 账号后，在设置页保存这个 WebHook 地址。

2
注册单号

把密钥放进请求头的 17token，单号通过 number 传递，一次最多 40 个。返回 code: 0 且 accepted 有内容，即注册成功。

curl -X POST \
  --header '17token: YOUR_TOKEN' \
  --header 'Content-Type: application/json' \
  --data '[{"number": "RR123456789CN"}]' \
  https://api.17track.net/track/v2.4/register
3
监听推送

注册成功后几秒内会收到第一次跟踪结果（受网络和运输商服务影响，可能延迟 5 分钟以上）。收到 TRACKING_UPDATED 事件即表示自动跟踪并推送成功。

{
  "event": "TRACKING_UPDATED",
  "data": {
    "number": "RR123456789CN",
    "carrier": 3011
  }
}

密钥与认证

所有接口只接受带有唯一密钥的请求。使用 API 账号登录后，在设置页获取密钥，放入每个请求头的 17token 中。

不建议在网页前端调用 API，存在泄露密钥的风险。

在设置页点击「更改密钥」可以生成新密钥。新密钥最长有 5 分钟生效延迟，生效后旧密钥立即失效。

注意事项

  • 每个接口的请求频率上限为 3 req/s，超限返回 429。
  • 所有响应报文中的时间均为 UTC 格式，没有信息的属性统一返回 null。
  • 物流单号与运输商代码组合成数据的唯一标识。
  • 请将调用服务升级到 TLSv1.2 或更高版本，非安全协议将无法建立连接。

自动跟踪

首次注册成功后几秒内返回结果
6~12 小时按主状态定期跟踪；异常或妥投包裹每 24 小时一次
30 天连续 30 天无事件更新则停止跟踪
签收 +15 天签收后再跟踪 15 天，无更新则停止
90 天停止跟踪的单号保留 90 天后删除

停止跟踪的单号可以重启跟踪 1 次。

扣费说明

  • 常规运输商每个物流单号计 1 单，自动跟踪期间不重复扣费。
  • 同一单号更换运输商后重新注册成功，按 1 单扣费。
  • 删除单号后再次注册成功，会重新扣减一次单量。
  • 特殊渠道运输商需先开通授权，扣费标准因渠道而异。

请求与响应

所有接口统一使用 HTTP POST 提交，请求和响应均为 UTF-8 编码的 JSON。

项目说明
请求地址https://api.17track.net/track/v2.4/{接口名称}
请求头 17token必填，内容为密钥
请求头 Content-Type必填，内容为 application/json
请求体序列化的 JSON 内容

响应格式

响应统一封装为 code 与 data。正常业务处理时，成功部分在 data.accepted，失败部分在 data.rejected，并附带错误代码。

{"code": 0, "data": {"accepted": [], "rejected": []}}

HTTP 状态码

200请求正常处理，具体结果需检查返回数据
401未授权、密钥错误、IP 不在白名单或账号被禁用
404请求的 URL 地址错误
429访问频率超出限制
500服务器错误
503服务临时不可用

推送策略

登录 API 账号，在设置页填入接收推送的 URL 并保存，再用「WebHook 测试」验证地址是否畅通。推送由队列控制发送，建议同样用队列处理接收到的信息。

  • 每次推送包含一个物流单号的全量信息。
  • WebHook URL 返回 HTTP 状态码 200 表示处理成功，其余状态码都视为推送失败。
  • 推送失败后重试 3 次，全部失败则等到下次自动跟踪时再推送。

重试节奏

第 1 次立即推送
第 2 次10 分钟后
第 3 次30 分钟后
第 4 次1 小时后

推送通知类型

TRACKING_UPDATED更新跟踪通知自动跟踪后物流信息有变化即刻推送，包含该单号的全量信息；没有变化则不推送。
TRACKING_STOPPED停止跟踪通知单号因系统规则停止跟踪时推送，之后不再有更新通知，可通过重启跟踪接口恢复。

签名验证

每次推送都在请求头的 sign 中携带签名，建议先验证签名再使用推送内容。

STEP 1拼接待签名内容取原始的更新跟踪通知报文，不做任何修改，拼接 / 和密钥。
STEP 2SHA256 编码对拼接结果做 SHA256 十六进制编码，得到签名结果。
STEP 3比较结果与推送请求头 sign 一致即验证通过，说明推送来自 17TRACK。
// 推送报文 + "/" + 密钥
{"event":"TRACKING_UPDATED","data":{"number":"RR123456789CN","carrier":3011,"tag":null}}/123456ABCDEF

// SHA256 十六进制编码后与请求头 sign 比较
sign == sha256Hex(rawBody + "/" + token)
